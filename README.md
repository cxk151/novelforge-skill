# 🔥 NovelForge 小说锻造台

### 为长篇小说和连载网文准备的创作 Skill

**能写出一章不难，难的是写到一百章以后，还记得第一章埋下了什么。**

NovelForge 不只负责续写。它会先弄清楚哪些设定已经确认、哪些只是备选、人物此刻知道什么、上一章把剧情推到了哪里，然后再动笔。

## 😵 普通小说 Skill 最容易卡在哪里

很多小说 Skill 刚开始很好用：给一段设定，马上就能写出一章。但篇幅一长，问题就慢慢冒出来了：

- 前文刚说角色在外地，下一章人已经坐在公司开会；
- 人物改过名字，几章以后旧名又冒了出来；
- 用户只让改一句对白，结果整段剧情都被顺手重写；
- 大纲、旧稿和新要求互相冲突，AI 挑了一个版本直接往下写；
- 伏笔埋了不少，后面既不提醒，也不知道该怎么收；
- 为了“去 AI 味”只会删几个常见词，人物说话还是一个腔调；
- 换个聊天窗口，之前商量了几十轮的细节几乎要从头解释。

这些问题不是“再写一条更长的提示词”就能解决的。长篇小说缺的不是一次灵感，而是一套能长期保存事实、记录修改和约束续写的工作方式。

## 🔍 NovelForge 有什么不同

NovelForge 把小说当成一个持续更新的项目。正文、大纲、人物状态、伏笔和修改记录各管各的，写下一章时只拿真正相关的内容。

| 常见做法 | 容易出现的问题 | NovelForge 的处理方式 |
| --- | --- | --- |
| 依赖当前聊天记忆前文 | 聊天变长后遗漏细节 | 把已确认设定和章节事实单独保存 |
| 把大纲和正文混在一起 | 未采用的方案也被当成正史 | 明确区分正式设定、草稿、备选和废案 |
| 每次续写都塞入大量原文 | 上下文很长，重点反而丢失 | 根据本章人物和事件组装精简上下文 |
| 用户提出新要求后直接开写 | 新旧版本互相污染 | 先检查冲突，再按明确的优先级采用版本 |
| 用禁词表处理“AI味” | 换了词，表达方式还是机械 | 检查对白关系、人物口吻、重复反应和解释性旁白 |
| 只检查语句是否通顺 | 时间、位置和知情范围仍会穿帮 | 同时核对人物、时间、道具、因果和知识来源 |
| 修改时整章重新生成 | 原本满意的内容也被改坏 | 先划定必须改、允许联动和禁止触碰的范围 |

简单说，普通续写工具关心“这一章写得像不像”；NovelForge 还会追问：

- 这件事接得上上一章吗？
- 这个人为什么知道这条消息？
- 关键道具从哪里来的？
- 新写法有没有撞上已经确认的设定？
- 这一章结束后，人物和局面到底发生了什么变化？

## 🧰 NovelForge 能做什么

### 立项与规划

- 判断一个点子适不适合写成长篇；
- 整理核心卖点、主角动力和持续冲突来源；
- 拆分总纲、分卷、阶段、事件、章节和场景；
- 给不同剧情路线列出收益、风险及后续影响。

### 设定与人物

- 记录人物姓名、称谓、身份、位置、关系和当前目标；
- 区分“读者知道”“主角知道”和“配角不知道”；
- 追踪世界规则、势力、能力、系统奖励和道具去向；
- 新设定出现时，检查它是补充、修改还是与旧设定冲突。

### 正文与续写

- 根据目标字数写完整章节，不用概要冒充正文；
- 承接上一章的动作、时间、情绪和未解决问题；
- 为当前章节生成任务卡，避免写着写着跑去解决另一个事件；
- 写完后生成事实摘要，留给下一章使用。

### 修改与审校

- 支持局部修改、统一改名、拆章、合章和剧情路线调整；
- 保护用户明确要求保留的正文；
- 检查人物串线、时间矛盾、道具凭空出现和反派突然降智；
- 找出对白排队讲道理、全员同声同气、重复解释等明显AI写作痕迹。

### 连载与交接

- 记录当前写到哪一卷、哪件事、哪个章节；
- 管理尚未回收的伏笔和还没兑现的剧情承诺；
- 整理读者反馈，但不会因为一条评论就推翻整本书；
- 生成交接包，让新聊天、新模型或合作者知道应该接着哪里写。

## 🧠 它怎么记住一部长篇

NovelForge 不会每次续写都把整部小说重新读一遍。它把信息分成四层：

1. **长期不变的内容**：书名、主角身份、世界规则和写作禁区。
2. **正在变化的内容**：当前事件、人物关系、伤势、能力和道具。
3. **最近发生的内容**：近期章节里已经发生的事实。
4. **眼前这一章需要的内容**：上一章结尾、本章任务和登场人物。

例如写第53章时，它不需要把前52章全部塞进上下文，但会带上第7章尚未回收的伏笔——前提是这条伏笔与当前事件有关。

## 🛡️ 新旧设定打架时听谁的

默认顺序如下：

```text
用户这次明确提出的新要求
    ↓
当前有效设定
    ↓
用户确认过的正文
    ↓
正式交接文档
    ↓
尚未写进正文的大纲
    ↓
已经废弃的版本
    ↓
AI 自己的推测
```

能判断时按顺序执行；不能判断时把冲突列出来询问，不会把两个版本硬拼在一起。

## 🎭 “去 AI 味”不只是换几个词

NovelForge 重点检查的是表达习惯：

- 角色是不是都用同一种句式说话；
- 对白有没有真正回应上一句；
- 动作已经表达清楚后，旁白是不是又解释了一遍；
- 配角是不是除了震惊、沉默和倒吸凉气就没别的反应；
- 主角是不是每句话都像提前写好的金句；
- 一场冲突是不是只有嘴上赢了，却没有实际结果；
- 开启新事件的方法是不是连续几次都一样。

它不会看到“空气仿佛凝固”就机械删除，而是先判断这句话在场景里有没有作用。

## 📚 当前题材预设

- 都市现实与都市系统
- 玄幻、高武与修仙
- 悬疑与推理
- 恋爱与情感

题材预设只补充需要特别检查的内容。例如高武会关注战力和能力代价，悬疑会关注线索来源和人物知情范围。

## 📦 安装

将本仓库放入个人 Skill 目录，或让 Codex Skill Installer 从本仓库安装。安装后可以显式调用：

```text
$novelforge
```

当任务明显涉及长篇小说创作时，ChatGPT/Codex 也可以自动选择它。

## ⚡ 快速开始

### 直接告诉它要做什么

```text
使用 $novelforge 新建一本都市系统文，目标平台番茄小说，规划100万字。
```

```text
使用 $novelforge 读取当前设定和最近五章摘要，完整续写第十二章。
```

```text
使用 $novelforge 检查第1—20章的人名、时间线、道具来源和人物知情范围。
```

```text
使用 $novelforge 只把“吴倩”统一改为“李倩”，其他剧情和表达不要动。
```

### 使用附带工具

```bash
python scripts/novelforge.py init ./my-novel --title "我的小说"
python scripts/novelforge.py validate ./my-novel
python scripts/novelforge.py context ./my-novel --chapter 12
python scripts/novelforge.py audit ./my-novel
python scripts/novelforge.py count ./my-novel/manuscript/第012章.md
```

## 🗂️ 小说项目长什么样

```text
my-novel/
├── canon.yaml                 # 当前有效设定
├── constraints.md             # 必须做到、必须避免、不能改的内容
├── change-log.yaml            # 每次修改了什么，为什么改
├── story-bible/               # 人物、世界、势力、能力和道具
├── planning/                  # 总纲、卷纲、事件、章节和备选路线
├── continuity/                # 时间线、当前状态、未回收伏笔
├── summaries/                 # 每章真正发生了什么
├── manuscript/                # 正文
└── exports/                   # 交接文档和检查结果
```

## 🔧 附带的检查工具

工具使用 Python 标准库，不需要额外安装依赖。目前支持：

- 创建标准小说项目；
- 检查项目文件是否齐全；
- 统计中文字符、英文单词和非空白字符；
- 找出重复章节号、空章节和章节序号缺口；
- 列出写指定章节时需要读取的文件。

这些工具负责能明确判断的问题。人物反应是否自然、冲突是否有趣，仍由创作流程结合正文判断。
