## ✨ 为什么需要 NovelForge

普通对话式写作很擅长写“眼前这一段”，却容易在长篇连载中出现人物串线、时间冲突、设定复活、旧稿覆盖新稿、伏笔失踪，以及越来越明显的模板化表达。

NovelForge 将小说视为一个具有**权威基线、动态状态、版本历史和人物知识边界**的长期项目。它把确定性问题交给脚本，把创造性判断交给模型，让创作自由和工程可靠性同时存在。

> 你负责决定故事往哪里走，NovelForge 负责记住它为什么能走到这里。

## 🧠 长篇创作的“四层记忆”

1. **永久基线**：书名、人物身份、世界规则、绝对不能违反的创作要求。
2. **阶段状态**：当前卷、事件进度、人物关系、能力和道具状态。
3. **近期记忆**：最近章节的事实摘要、未解决冲突和新增信息。
4. **即时上下文**：上一章正文、本章任务、场景参与者与停止位置。

它不会为了写下一章粗暴吞下整部百万字正文，而是按任务组装最小有效上下文。

## 🛡️ 防止设定打架

NovelForge 使用明确的内容权威顺序：

```text
用户当前明确指令
    ↓
最新有效项目基线
    ↓
用户确认过的正文
    ↓
最新正式交接文档
    ↓
当前大纲
    ↓
已经废弃的历史版本
    ↓
模型自行推测
```

发现冲突时，它会展示冲突来源和采用依据，而不是悄悄把两个版本缝在一起。

## 🎭 不止是“去 AI 味”

NovelForge 不依赖一份机械禁词表，而是检查真正影响阅读体验的结构性问题：

- 所有人说话像同一个人；
- 对白排队讲道理，却没有试探、回避、施压和误解；
- 动作已经说明情绪，旁白又解释一遍；
- 配角只会震惊，反派只会突然降智；
- 每章都用电话、私信或陌生人上门开启新事件；
- 每句话都想当金句，反而失去人物生活感；
- 只完成口头打脸，没有现实后果与事件余波。

## 📚 题材支持

当前内置都市现实与系统、玄幻高武与修仙、悬疑推理、恋爱情感预设。预设只增加该题材真正需要的检查项，不会把某一本小说的固定套路强加给所有项目。

## 📦 安装

将本仓库放入个人 Skill 目录，或让 Codex Skill Installer 从本仓库安装。安装完成后，在 Codex 中输入：

```text
$novelforge
```

也可以让 ChatGPT/Codex 根据任务自动调用。

## ⚡ 快速开始

### 用自然语言创作

```text
使用 $novelforge 新建一本都市系统文，目标平台番茄小说，规划100万字。
```

```text
使用 $novelforge 读取项目基线和最近五章摘要，完整续写第十二章。
```

```text
使用 $novelforge 检查第1—20章的人名、时间线、道具来源和人物知识边界。
```

```text
使用 $novelforge 只把“吴倩”统一改为“李倩”，其他剧情和表达不要动。
```

### 使用项目工具

```bash
python scripts/novelforge.py init ./my-novel --title "我的小说"
python scripts/novelforge.py validate ./my-novel
python scripts/novelforge.py context ./my-novel --chapter 12
python scripts/novelforge.py audit ./my-novel
python scripts/novelforge.py count ./my-novel/manuscript/第012章.md
```

## 🗂️ 项目结构

```text
my-novel/
├── canon.yaml                 # 当前最高权威设定
├── constraints.md             # 必须做到、必须避免、锁定内容
├── change-log.yaml            # 每次有效修改的来源与范围
├── story-bible/               # 人物、世界、势力、能力、道具
├── planning/                  # 总纲、卷纲、事件、章节与备选路线
├── continuity/                # 时间线、当前状态、未回收伏笔
├── summaries/                 # 章节事实摘要
├── manuscript/                # 正文
└── exports/                   # 交接、审校与成稿输出
```

## 🧭 设计理念

- **作者拥有最终解释权**：AI 的建议不是自动生效的设定。
- **正文高于旧大纲**：已确认事实不会被过时规划反向覆盖。
- **修改必须有边界**：局部修改不等于授权整体重写。
- **备选路线不污染正史**：未选择方案永远留在候选区。
- **文学判断不做伪量化**：脚本负责确定性检查，模型负责语境和审美。
- **上下文按需加载**：功能再全面，也不一次塞入所有规则。
