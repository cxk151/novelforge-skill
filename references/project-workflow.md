# Project workflow

## New project

Capture premise, genre, audience/platform, intended experience, point of view, tense, length, update cadence, content boundaries, structure, and ending policy. Infer harmless defaults, label them, and ask only when different answers materially change the design.

Test the premise for a repeatable story engine: protagonist drive, recurring conflict sources, escalation space, costs or limits, relationship movement, and at least three distinct arc shapes. Flag premises that support a strong opening but not the requested length.

Create project files with `python scripts/novelforge.py init PATH --title "TITLE"`. Populate `canon.yaml` with accepted decisions, not speculation. Keep rejected and alternate ideas under `planning/options/`.

## Positioning

When requested, assess hook clarity, novelty, sustainability, audience promise, platform fit, opening strength, difficulty, and likely repetition. Separate observed market facts from creative recommendations. Browse current markets only when the user requests current information or it materially changes advice.

Competitive analysis may extract structure, pacing, positioning, and reader expectations. Do not reproduce protected prose or imitate a living author's signature voice.

## Existing project intake

Inventory manuscripts and planning files. Establish a current baseline before generating prose. Mark each source `active`, `confirmed`, `draft`, `option`, or `superseded`. Resolve contradictory word-count or naming rules using the authority order in `SKILL.md` and record the resolution.
