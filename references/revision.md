# Revision workflow

Before editing, define `must_change`, `may_adjust`, and `protected`. Prefer the narrowest repair. A rename is not permission to rewrite scenes; a logic repair may adjust necessary setup but must disclose knock-on changes.

For split/merge operations, preserve event order, information timing, causal links, and protected prose. Rebuild openings and endings so each resulting chapter has a function; do not cut only by word count.

For route changes, inspect downstream effects on characters, clues, timeline, props, foreshadowing, summaries, and future plans. Mark replaced content as superseded.

When useful, report location, before/after meaning, reason, affected records, and remaining risks. Do not hide creative changes inside proofreading.
